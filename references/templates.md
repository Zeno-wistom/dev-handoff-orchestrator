# 交接与汇报模板

只按真实证据填写内容；没有的信息写「未知」或「未验证」。用户需要复制时，把完整 Prompt 放在一个独立代码块中。

## 日常开发汇报

```text
大白话结论：本轮用户能做什么、哪里还没验证。
项目总进度：[八格或????????] 已验收/总阶段（有明确阶段时）
当前阶段：[八格或????????] 已完成/总子任务（有明确阶段时）
本轮完成：具体成果
实际测试：测试内容、结果；未执行则写未验证
待决策/风险：需要用户决定的取舍；没有就写无
当前步骤：...
下一步：...
进度依据：任务清单/本轮验收及实际测试证据
```

常规功能汇报保持简短；文件位置、日志或命令有助于判断时再附上。仅在新会话、跨阶段、复杂阻塞或用户明确要求时使用完整交接。

## 双层进度规则

- 项目层统计已验收阶段；当前阶段统计满足验收条件的子任务。不能将代码行、测试用例、文件数和阶段数混用。
- 八格按 `floor(8 * 已完成 / 总数)` 绘制，`0 ≤ 已完成 ≤ 总数` 且总数大于零时才计算。只有可靠任务数量才能给出数字；未知显示 `[????????] 未知`。
- 数量进度不代表耗时，分母变化需说明。顾问建议、已写未测、阻塞和待批事项不计入验收完成。
- 简单一次性任务无需强制显示项目进度。

## 需要用户决定的事项

```text
需要你决定：...
方案 A：对效果、时间或费用的具体影响
方案 B：对效果、时间或费用的具体影响
我的推荐：...（原因）
目前可以继续的部分：...
等待决定的部分：...
```

## Codex → ChatGPT 完整交接 Prompt

把下面六项合在**一个可复制代码块**；不要携带无关历史或秘密信息。

```text
你是本项目的 ChatGPT 顾问。请先用大白话解释当前状态，再指出关键问题和下一步。顾问建议不等于代码已执行或用户已批准的决定。

1. 当前目标
当前功能、项目定位、必要的版本信息、双层进度与依据。

2. 已完成的工作
已实现内容、关键文件、实际验证结果和未验证事项。

3. 关键已批准决定
用户已经明确同意的方向、约束及必要出处；不确定就标明。

4. 当前问题及必要证据
真实错误、最小复现信息、风险；已知的上下文状态，无数据则写未知。

5. 下一步任务
明确要解决的事项和验收条件；需要你帮助解释、分析或整理下一轮指令的重点。

6. 禁止或尚未获批的改动
禁止事项、已否决方向，以及需要用户决定的重要取舍。
```

## ChatGPT → Codex 执行 Prompt

```text
使用 $dev-handoff-orchestrator 继续当前项目。
目标与验收标准：……
用户已批准的决定：……（有依据）
参考资料与建议：……（注明尚待验证部分）
修改范围：……
禁止事项与待审批取舍：……
执行：完成实现和必要测试；根据实际结果汇报成果、双层进度、未验证事项、风险和下一步。
```
